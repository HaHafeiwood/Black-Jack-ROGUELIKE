# 工坊純檢視與種子確定性修復

狀態：已實作（2026-09-16）。本次只修復流程確定性，不修改任何平衡資料、價格、素材價值、商品刷新功能或石像鬼。

## 正式階段入口

- 戰士正式進入商店、每大關固定休息點或初次整備時，初始化本次工坊造訪並生成三張替換候選；即使不開工坊也照常生成。
- 候選使用既有共用種子亂數，每張依原 `randomCard` 方法生成。相同造訪只生成一次。
- 工坊開關、選牌檢視、倍率查看、進階區展開與返回皆只讀既有候選，不抽牌、不推進結果亂數。
- 成功改牌後保留原候選與已使用狀態，所有結構改牌操作停用。檢視不建立新造訪。
- 商店以樓層節點識別執行期間造訪。正常重入只重繪，不重置商品、購買紀錄、刷新價格、入店治療或工坊。既有付費商品刷新仍依原規則重抽商品，不刷新工坊候選。
- 隨機休息事件不建立工坊。

## 關卡入口存檔

- 保留入口快照：商店／休息的節點判定與初始化前記錄種子狀態。候選與執行期間造訪快取不加入存檔。
- 讀檔丟棄執行期間快取，從入口種子重新判定節點並初始化，重現相同候選與後續亂數進度。
- 進關後改牌、付款、素材消耗與本次使用狀態不寫回入口存檔。
- 初次整備是第0層流程完成後、第一場戰鬥前的獨立入口，僅新增 `entryPhase: initialPreparation` 識別。於生成候選前建立快照；讀檔重新進入整備，不略過。
- 初次整備完成或跳過後清除識別並建立第一關入口快照；往後讀檔不再次提供初次整備。沒有新識別的舊存檔保留原遷移行為，不把已進關角色拉回整備。
- 正常同節點重入沿用執行期間資料；讀檔重播入口是不同路徑，不保存一般半途狀態。

## 驗收

`gameplay-test.cjs` 對商店、固定休息、初次整備各建立「不改牌」及「相同素材替換」成對案例：一組反覆檢視，另一組不檢視。

比較三張候選、`rngState`、`rngCalls`、牌庫、金幣、素材、改牌次數、商品與購買紀錄；驗證非法操作、成功使用後檢視、正常重入、付費商品刷新與兩次入口讀檔。離開後比較自然下一節點、敵人與手牌，另以相同指定遭遇比較發牌及後續種子節點判定。

初次整備的「跳過／完成並出發」是正式結束階段，不是純檢視關閉；測試中兩組只各結束一次。

## 新版亂數序列

替換候選原本依開啟次數生成，現在每次符合資格的正式入口固定生成一次（共六次既有結果亂數呼叫）。因此新版不保證沿用修復前的後續序列；新版相同種子與相同實際操作，不論檢視次數，必須得到相同結果。沒有新增付費或免費候選刷新。
